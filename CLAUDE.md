This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Entry for the Crusoe × Cerebral Valley **Recursive Agents Hackathon** (Sat Oct 17, 2026, San Francisco). Theme: a team of agents you can walk away from — agents that take a goal, plan, spawn and delegate to sub-agents, communicate, check their own progress, recover from failures, and keep running. Everything is built on **Crusoe Managed Inference** (OpenAI-compatible serverless API).

Team research lives in `docs/research/` (start with `docs/research/README.md`). It covers building our own Obsidian-style knowledge base for agent memory, GPT-6 Astra vs Claude for Blender and 3D work, rendering San Francisco buildings in three.js, floorplan datasets and 2D-to-3D rendering, and building energy simulation. Read the relevant file before working on any of those.

## Product: Workbench (in progress)

A ChatGPT-desktop-style chat where the agent also builds a **process**: a numbered plan of steps plus typed, versioned **artifacts** (forms, markdown documents, sandboxed HTML) with lineage. Users come back later and click artifacts to recall details; editing an earlier form marks everything built from it stale, and the agent either patches cheaply with parallel sub-agents or asks before an expensive redo.

- **Schema** (`src/lib/server/db/schema.ts`): `conversations`; `messages` (OpenAI chat format, append-only for prefix caching; `meta` is UI-only and never sent to the model; `meta.kind = 'error'` rows are filtered out of history); `steps`; `artifacts` + `artifact_versions` (every change is a version; `data` holds form answers; each version records cost and duration of the work that produced it); `artifact_deps` (upstream → downstream lineage); `usage` (one row per model call).
- **Data access**: `src/lib/server/store.ts`, including `downstreamOf` (transitive stale set) and `estimateRedo` (sums the cost/duration of the last non-user version of each stale artifact).
- **Crusoe client** (`src/lib/server/crusoe.ts`): streaming fetch, jittered backoff on 429/503 before the first byte, per-model throttle on `x-ratelimit-remaining-requests`, reads `reasoning_content`/`reasoning`, price table for cost.
- **Agent** (`src/lib/server/agent/`): `prompt.ts` (stable system prompt; edit-policy rules), `tools.ts` (`set_plan`, `update_step`, `create_form`, `create_artifact`, `update_artifact`, `read_artifact`, `quick_edit`, `mark_fresh`, `propose_redo`; schema order is part of the cached prefix), `run.ts` (loop, max 12 turns, one run per conversation, tool calls run concurrently and results are appended in call order), `subagent.ts` (`quick_edit` on the fast model), `edits.ts` (form submit / user edit / proposal answer → `[Form submitted]` / `[Edit]` / `[Approved]`·`[Declined]` messages; edits carry a field diff, the stale list and a redo estimate).
- **Forms**: the agent sends a `FormSpec` via `create_form`; the app renders it (`FormView`), never agent HTML. Every answer is free text (`type` is `text` or `textarea`) so "idk" always fits; `options` are suggestion chips that always toggle in a comma-separated answer (GLM ignored a `multiple` flag, so it was dropped). `normalizeFormSpec` converts older types (select/radio → suggestions, checkbox → Yes/No, checkboxes → multiple, date/number/email → text) and `answerText` renders legacy answers. No field is required; blanks reach the agent as `(empty)`. The system prompt has a "Form design" section: 3-6 questions, one field per idea (amount with currency, ranges, a date with its flexibility, yes/no with details), examples in placeholders, 3-5 chips, short labels, no boilerplate description. With it the apartment-search form went from 12 fields to 6. Placeholders are one short US-style example ("e.g. under $1500"); the prompt lists good and bad examples because GLM ignores bare word limits. Placeholders and chips must be typeable: the prompt says so, and `typeable()` in `normalizeFormSpec` rewrites ±, en/em dashes, ≤/≥, →, curly quotes and … in options and placeholders.
  - Questions are edited inline in the form itself (`FormView` `editQuestions`): question and help text are auto-growing textareas that look like plain text until focused (transparent border kept, `-mx-2` offset, so nothing shifts); clearing a question's text removes it; "+ Add question" adds one. No hover tools, no separate editor (the old `QuestionEditor` was removed).
  - Unanswered form: question edits autosave on blur via `PUT /api/conversations/[id]/artifacts/[artifactId]` (`edits.editQuestions`, no agent run); submit waits for a pending save.
  - Answered form: stays editable in place (no Edit button). "Save and tell the agent" and Discard appear only once something changed (`saveWhenChanged`); saving sends one `artifact_edit` with `values` and `spec`. `diffSpecs` lists question changes, then answer changes, and downstream artifacts go stale.
  - Existing questions keep their `name`; new ones get `fieldName(label)`, never reusing a removed question's name. Submission and edit messages list answers with their labels (`- Label (name): value`) plus a JSON block.
- **Widgets** (`kind: 'widget'`): agent-written interactive input for what forms handle badly (sliders with live totals, ranking, grids). `create_widget` takes petite-vue HTML (`v-scope`, `v-model`, `@click`, getters for computed values) plus an optional `data_schema`; `normalizeWidget` (`#lib/widgets.ts`) rejects HTML without `$submit` or with external resources. `Widget.svelte` runs it in an `iframe sandbox="allow-scripts"` (opaque origin) whose CSP allows inline scripts and `unsafe-eval` (petite-vue compiles expressions with `new Function`) but no network; the petite-vue IIFE is inlined via `../../../node_modules/petite-vue/dist/petite-vue.iife.js?raw` (its package exports hide `dist/`). A bridge exposes `$submit(obj)` and `$initial` (last submitted data), reports height, and relays errors; the parent only accepts messages whose `source` is its own frame. Submissions go through `form_submit` and are checked with `checkSubmission` (object, ≤20k chars, schema); edits are diffed per leaf path (`diffData`). The agent may fix an unanswered widget in place with `update_artifact` (content = new html).
- **Embedded inputs**: forms and widgets stay inline in the chat where the agent asked (`InlineInput.svelte`), answered or not: with "✓ Answered"; forms stay editable, widgets have a Change button. No Open button: the inline card is the artifact. Forms and widgets don't show versions anywhere (history is still stored for diffs and estimates); documents and HTML keep their version strip and diffs.
- **Blueprints** (`kind: 'blueprint'`, `BlueprintSpec`): a staged 3D walkthrough of one (often fictional) property, made by the `create_blueprint` tool and embedded in the chat (`BlueprintEmbed.svelte`) like forms. Two views: "Living room" is James's photoreal showcase room (`RoomScene.svelte` wraps `#lib/room-showcase/scene.ts`, loaded only when scrolled into view because its assets are ~24 MB), and "Floor plan" is the unit layout, a bundled plan from `#lib/floorplan/catalog.ts` drawn as an SVG sketch (`PlanSketch.svelte`) that opens in the 3D floor-plan viewer. The agent tailors title, fictional address, summary and highlights to the user's answers; the 3D itself is staged. The prompt makes it call `create_blueprint` whenever it describes a target unit or the user asks to see/show/render a place, and never to point the user at the process panel instead. An identical blueprint (same title, plan, address) is reused rather than duplicated, and the chat embeds a blueprint at its latest mention. The showcase room renders through an EffectComposer with a GTAO ambient-occlusion pass (radius 0.5 m; `ambientOcclusion: false` or `/plans/room?ao=0` turns it off); the floor-plan viewer already had GTAO in its High quality mode. `/plans` is now a card index of blueprint artifacts (`store.listBlueprints`) linking back to their conversations; the old viewer moved to `/plans/view` (old `/plans?plan=…` links redirect), and `/plans/view` and `/plans/room` accept `?c=<conversation>&a=<artifact>` for a "From conversation" link.
- **Redo approval**: for large changes the agent calls `propose_redo`; the tool result's `meta` (`kind: 'proposal'`, keyed by the tool call id) renders as `ProposalCard` with a grounded estimate (`store.estimateRedo` plus optional extra cost/time) and Approve/Keep buttons. The answer is a `proposal_reply` user message; a proposal can only be answered once.
- **Redo in place**: `[Approved]` tells the agent to `update_artifact` the same ids (with an optional new `title`, via `store.renameArtifact`); without that, gpt-oss created a replacement artifact and left the old one stale.
- **Steps**: submitting the last open form of an active step marks it done (`store.completeStepIfAnswered`).
- **Step status** follows artifacts: `store.syncStepStatus` turns a done step `stale` while any of its artifacts is stale/updating and back to `done` when they're fixed.
- **API**: `POST /api/conversations`; `GET|DELETE /api/conversations/[id]`; `POST /api/conversations/[id]/run` (body `message` | `form_submit` | `artifact_edit` | `proposal_reply`; streams NDJSON `RunEvent`s from `#lib/types.ts`); `POST /api/conversations/[id]/cancel`. Full frontend-facing reference, kept in sync with the code: `docs/api.md`.
- **Self-check** (`checkFinalAnswer` in `run.ts`): before a final reply goes to the user, every `art_xxxxxxxx` it mentions must exist; otherwise a `[Check]` user message (`meta.kind = 'check'`, shown as a violet chip) sends the agent back, at most twice per run. gpt-oss did announce an artifact it never created in the first real run.
- **Agent loop details**: tool calls run in call order (a form can reference a step that `set_plan` created in the same turn); only consecutive `quick_edit` calls run in parallel.
- **UI**: `/` is the start page (creates a conversation, then runs); `/c/[id]` loads `conversationState` (`depends('app:conversation')`) and renders `components/Workspace.svelte`: chat in the middle, with pending forms embedded inline where the agent asked and other artifacts as cards; on the right, `ProcessPanel` (steps, artifacts per step, usage and cache-hit rate) or `ArtifactView` (versions, lineage links, edit → `artifact_edit`). The open artifact is in `?a=<id>`, so links deep-link. `ArtifactView` highlights form answers changed since the previous version and shows a line diff for documents/HTML (`#lib/diff.ts`). `/library` searches every artifact across conversations (`store.searchArtifacts`: title, content, answers, conversation title) with kind filters. `src/lib/client/run.svelte.ts` holds the live run state and invalidates on `changed` events. HTML artifacts render in an iframe with `sandbox="allow-scripts"`, no same-origin and a CSP that blocks network; markdown is sanitized with DOMPurify in the browser.
- **Svelte/Kit 3 gotchas hit so far**: `browser` comes from `$app/env` (`$app/environment` is deprecated and untyped); `goto` options are `reset`/`replace`, not `noScroll`/`keepFocus`; `page.url.searchParams` is read-only (copy via `new URLSearchParams(page.url.search)`); don't name a prop `state` (it clashes with the `$state` rune).
- **Mock agent** (`agent/mock.ts`) stands in for the model's judgment: editing `goal` or `audience` triggers `propose_redo`, other fields a `quick_edit`. Its tool call ids are random so proposal replies stay unique across restarts.
- **Real agent (gpt-oss-120b) behavior seen 2026-10-17**: calls one tool per turn (so ~3-7 model calls per user action, ~4-6s), follows the edit policy (small edit → parallel `quick_edit`s on V4 Flash; changed cuisine → `propose_redo`), 58-78% prompt-cache hits, about $0.001-0.002 per user action. It has no web access and will invent venues/phone numbers unless told; the prompt now requires labeling real-world specifics as unverified.
- **`zai-org/GLM-5.3-Flash` as agent (tested 2026-10-17, `CRUSOE_AGENT_MODEL=zai-org/GLM-5.3-Flash`)**: works with the same tools, and is more proactive: after one form it ran every remaining step (3 linked documents, 36s). It's about 2× the cost of gpt-oss ($0.011 vs ~$0.006 for the same flow) and 3-6× slower per action (7-36s), with 0% cache hits on the first turn. It skipped `propose_redo` on a cuisine change (patched everything with `quick_edit` instead) and claimed a retitle that `quick_edit` can't do. It was made the default afterwards, with the hardening below.
- **Hardening from real runs** (any model may break the tool schema; the server repairs or rejects instead of trusting it):
  - `runTool` never throws: a failing tool returns `{ ok: false, error }` to the model so it can retry, instead of ending the run. `coerceArgs` decodes arrays/objects sent as JSON strings.
  - `create_form` passes fields through `normalizeFormSpec` (`#lib/forms.ts`): missing labels come from the name, unknown types become `text`, choice fields without options are downgraded, unnamed/duplicate fields dropped (GLM omitted a required `label`).
  - Lineage fallback: if `create_artifact` has no `depends_on`, it links to the run's `sources` (the form submitted/artifact edited that started the run, plus anything `read_artifact` returned). GLM omitted `depends_on`, so edits marked nothing stale.
  - The `[Edit]` message itself carries the SMALL/LARGE rule (the newest message outweighs the system prompt); with it GLM proposes redos for cuisine/location changes and patches times/budgets.
  - `estimateRedo` uses the costliest non-user version (the real generation), not the latest cheap `quick_edit` patch.
  - `quick_edit` and `update_artifact` both take an optional `title`.
  - The run endpoint validates bodies (400 for invalid JSON, missing `artifactId`/`callId`, unknown `type`).
  - The system prompt's first line `Reasoning: medium` is gpt-oss syntax; other models ignore it.
- **Layout**: below `xl` the process/artifact panel overlays the chat and starts closed; below `md` the sidebar is hidden. Scroll rule: only the chat column, sidebar list, process/artifact panel bodies and the library list scroll vertically; the page itself never does. The agent map (`AgentMap.svelte`) never scrolls vertically: it scales its SVG down to the panel height (measured outside the scroller, with 32px reserved for padding and a scrollbar so the scale can't oscillate) and scrolls only along its timeline. Never use native `confirm()`/`alert()`/`prompt()`: the desktop app's browser pane suppresses them (`confirm` returns false instantly), which once made sidebar delete silently do nothing. For the demo, the sidebar ✕ deletes a conversation in one click.
- **Status (2026-10-17)**: verified end to end with the mock agent and the real Crusoe agent: goal → plan + inline form → submit → brief → small edit patched by a sub-agent; large edit → proposal → approve (redo) or decline (stays stale); version diffs; library search. Both default model IDs are confirmed against `/v1/models`.

## Gotchas that break code (section numbers refer to the doc)

- **Base URL** is `https://api.inference.crusoecloud.com/v1`. Old hostnames (`api.crusoe.ai`, `managed-inference-api-proxy.crusoecloud.com`) cause 404/429. §3.1, §3.5
- **Model IDs are exact and case-sensitive**, and Crusoe's web pages often spell them differently from the API (`Deepseek-V4-Flash` vs `DeepSeek`, `zai-org/` vs `zai/`, `Qwen/` vs `qwen/`). Copy `id` from `GET /v1/models`; a wrong ID returns `404 model_not_found`. §4.1, §5
- **Deprecated models still appear in official examples** (e.g. `meta-llama/Llama-3.3-70B-Instruct`, Kimi K2.6, GLM-5.1/5.2). Don't use them. §4.3
- **API keys can contain `$`**: in a shell, export with single quotes (`export CRUSOE_API_KEY='...'`); double quotes silently corrupt the key → 401/403. §3.3 **In `frontend/.env` single quotes don't help**: Vite (and so SvelteKit) expands `$name` inside .env values even when quoted, so each `$` must be `\$`. Use `npm run set-key` (hidden input, escapes for you), then `npm run models` to verify.
- **Rate limits are per project *per model***, resetting each minute: 30 RPM / 500K TPM without a payment method, 600 RPM / 2M TPM with one. Every agent-loop turn is a request, so parallel sub-agents hit 30 RPM fast. Spread roles across different models, throttle on the `x-ratelimit-remaining-*` headers, and retry 429/503 with jittered exponential backoff. §6
- **Reasoning models spend `max_tokens` on thinking.** Use ≥1024 and check `finish_reason == "length"` when `content` is empty. Read both `reasoning_content` and `reasoning`. Toggle thinking via `extra_body={"chat_template_kwargs": {...}}`; DeepSeek's native `"thinking": {"type": "enabled"}` returns 403. Toggles differ per model — check `supported_parameters` in `/v1/models`. §4.6, §7.2
- **Tool calling**: append the assistant message containing `tool_calls` *before* the `role: "tool"` results, or you get a 400. §7.3
